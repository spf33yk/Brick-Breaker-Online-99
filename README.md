# ブロック崩しオンライン99

バー1人 vs ブロック最大99人の非対称オンライン対戦ゲーム。画面はHTML / CSS / JavaScript、対戦サーバーはNode.jsで実装しています。外部パッケージやビルドは不要です。

## 起動

Node.js 22以降をインストールして、リポジトリで実行します。

```sh
node server.js
```

[http://localhost:3000](http://localhost:3000) を開きます。`npm start`も同じ処理です。テストは`node --test`（または`npm test`）。

1. プレイヤー名・チーム・カラー・制限時間を選んでルームを作成します。
2. 友達にルームコードまたは招待リンクを共有します。
3. 全員が入室したら、ホストが「バトル開始」を押します。
4. 終了後はホストがロビーに戻して再戦できます。

## ルール

| チーム | 人数 | 勝利条件 |
| --- | --- | --- |
| バー | 最大1人。不在ならCPU | 99体すべてのブロックを撃破 |
| ブロック | 最大99人。不足分は白色のCPU | 制限時間まで1体以上が生存 |

- 制限時間は2 / 3 / 5分（初期値3分）。ボール落下時は再発射します。
- ブロックは盤面上側のエリア内を自由に移動できます。撃破された人は観戦します。
- ブロック同士は接触せず重なれます。CPUは移動と回避を行い、スキルは使いません。
- プレイヤーカラーは開始前に5色から選択可能。CPUは白色固定です。
- 対戦中の途中参加は不可。通信が切れて15秒経過するとCPUに引き継ぎます。ホストの退出時は次の参加者がホストになります。

| チーム | キー | スキル | 効果 | クールタイム |
| --- | --- | --- | --- | --- |
| バー | Q | 影分身 | 現在のボール数を2倍にする（負荷対策で上限128個） | 20秒 |
| バー | E | ボム | ボール付近に4秒間、半径78の爆弾を発生。接触したブロックを即撃破 | 25秒 |
| ブロック | Q | ゴースト | 10秒間、移動速度1.8倍 | 20秒 |
| ブロック | E | 砂時計 | 5秒間無敵。ボール・ボムの両方を防ぐ | 30秒 |

クールタイムは発動直後から進みます。初回はすぐに使えます。これらの秒数、ボール落下時の扱い、CPUバー、ボムと無敵の優先関係は未指定部分の初期仕様です。

## 操作

- バー：マウス / タッチで盤面を指す、または左右矢印 / A・D。
- ブロック：矢印キー / WASD、または対戦中に表示される方向ボタン。
- スキル：Q・E、または画面のスキルボタン。
- 入力欄にフォーカスがあるときは、キーで移動・発動しません。盤面をクリックしてください。

## オンラインで公開する

このゲームは対戦状態をNode.jsプロセスで共有します。HTMLだけを配置するGitHub Pagesではオンライン対戦は動きません。

- Node.js常駐プロセスを実行できるサーバーで`node server.js`を起動します。`PORT`環境変数でポートを設定できます（初期値3000）。
- リバースプロキシでHTTPSを提供してください。`/events`はServer-Sent Eventsなので、レスポンスのバッファリングを無効にし、長時間接続を許可してください。元のHostヘッダーを転送してください。
- 全参加者が同一サーバーURLを開く必要があります。別の端末では`localhost`を共有せず、公開URL、または同じLAN内のホストのIPアドレスを使用します。
- ルームはメモリー内に保持し、再起動すると消えます。単一プロセスで運用してください。水平分散には共有ルーム管理が必要です。
- 100人の枠と99体のシミュレーションを実装していますが、100端末の同時接続負荷試験は未実施です。本番公開前に実際の環境で帯域・CPU・接続上限を測定してください。

### Docker

```sh
docker build -t brick-breaker-99 .
docker run --rm -p 3000:3000 brick-breaker-99
```

## 構成

- `public/index.html` / `style.css` / `app.js`：日本語UI・Canvas描画・入力。
- `src/game.js`：移動・当たり判定・スキル・勝敗。サーバーが正とする状態。
- `server.js`：静的配信・ルーム管理・認証トークン・SSE配信・入力API。
- `test/`：ルール単体テストと、実サーバーでの複数クライアント同期テスト。

シミュレーションは約60Hz、状態配信は約15Hz。入力は最大約14Hzで送信し、700ms以上更新のない入力は無効にします。クライアントは描画と操作の送信だけを担当し、勝敗やスキル発動可否はサーバーが判定します。
